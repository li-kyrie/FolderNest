# FolderNest 2.1.0

Windows 中文文件保留期限管理工具。目录加入监控时建立计时，文件变化刷新计时，到期后在线提醒；用户在清单中选择并确认，才移入回收站或永久删除。

C# / .NET 10 + WPF + SQLite，自包含便携 `FolderNest.exe`。无需安装、无需另装 .NET，不依赖 PowerShell/CMD/VBS。程序可以放在 D/E 盘等可写位置。

## 快速开始

1. 解压便携包到自己选择的位置，双击 `FolderNest.exe`。本机正式入口：`D:\FolderNest\FolderNest.exe`。
2. 点击“添加监控目录”，选择真实文件夹，设置保留天数、删除模式和启用状态。
3. 保存后目录立即显示，现有文件从本次加入时开始计时。旧修改日期不会让新加入的文件立即到期。
4. 后台任务自动维护，不需要部署/卸载/勾选任务。“设置”中可修改每日时间（默认本地 02:00，24 小时制）、日志限额和新目录默认删除方式。
5. 有到期项的日子发送系统托盘通知。点击通知或“查看到期清单”，取消勾选不想清理的项目，再确认处理。

本机便携包：`D:\FolderNest-Portable-v2.1.0-win-x64.zip`。ZIP 不含个人配置、计时、日志或开发工具。

## 界面与常用操作

界面说明：

> 监控计时：目录加入监控开始计时，修改文件刷新时间
>
> 后台扫描：每天02：00＋登录补扫

每日时间可在设置里修改，说明同步更新。

| 操作 | 作用 |
| --- | --- |
| 添加监控目录 | 建立独立 ID 和初始计时；自动确保每日、登录两条全局启动任务存在 |
| 启用/停用选中 | 仅作用于当前选择的行；混合状态统一启用，全部启用则停用。保留计时记录，日历时间不冻结 |
| 删除监控任务 | 独立勾选窗口，可从全部目录中选择；只删除所选配置及计时，不删除真实文件。删完再加会重新计时 |
| 重置计时 | 独立勾选窗口；勾选整个目录，或展开后只选文件/一级子文件夹。从确认执行时重新计时，不改文件日期 |
| 扫描选中 / 扫描全部启用 | 手动校验所选启用目录/全部启用目录；未选中不会误扫描全部 |
| 全选 / 全不选 | 位于目录列表右上角；Ctrl 多选、Shift 范围选择仍保留 |
| 左侧排序柄 / 上移、下移 | 拖动单行排序或用按钮调整所选行的位置，顺序持久保存，不改变计时；不再提供拖动框选 |
| 双击路径 | 直接编辑，检查路径存在及是否重复/相互包含；无效输入提示且不保存，Esc 撤销草稿。换成新路径会清除该行旧路径计时 |
| 保留天数 | 1–36500 的整数；上下按钮和键盘上下键每次 ±1 |
| 状态 / 删除模式 | 固定下拉选项，合法修改立即保存 |
| 查看日志 | 使用记事本打开当前日志；轮换文件在同目录 |

删除窗口预先勾选主列表选中项；没有选择就不默认全删。重置窗口预先勾选主列表选中的目录，操作前会再次确认。未勾选范围不处理。停用目录也可以显式重置，但仍保持停用。

重置窗口里的一级子文件夹是**整体计时单元**，不是递归逐个文件设置。勾选整目录会在执行时重新读取全部当前项目；只勾选子项则仅处理已选择的路径。目录不可访问或指定项目消失时，该目录本次重置失败，原记录保留。

顶部功能区随行数自动变高，添加对话框保持 560×240，启用复选框单行。按钮操作保留仍存在的行对象和选择；被删除的行不能保留焦点。

## 到期清单与安全边界

- 根目录文件独立计时，每个一级子文件夹整体计时和清理。
- 添加监控时初始化现有项目；之后首次发现的新项目从发现时计时。修改按观察到变化的时刻刷新，不采用下载文件携带的旧日期。
- 停用不清空历史，也不冻结日历；再次启用后先校验文件变化。仅关闭窗口或退出程序不清空计时。删除监控、重置计时、改路径、删除数据文件会影响计时。
- 关机无法物理扫描，但已记录截止时间继续推进，登录后补算；未运行期间新进入的文件只能从首次发现保守计时。
- 所有启用目录自动跟踪。文件系统事件辅助记录活动，每 15 分钟全量校正，每日到点再检查；无需联网。
- 没有到期项不发通知、不弹清单；每天最多提醒一次，不追催。清单实时计算，不保存冻结的 Pending 队列。
- 清单支持路径筛选、勾选筛选项、取消全部勾选和本次删除模式覆盖。筛选**不会取消隐藏项的勾选**；确认框显示总项数及永久删除数。
- 执行前再次核对配置、计时、到期状态、路径及元数据指纹；变化、丢失、停用、访问失败的项目跳过并记录原因。取消勾选只影响本次，不是永久豁免。
- 不解析 `.lnk` 目标；跳过符号链接/目录联接等重解析点，拒绝清理内部包含链接的子文件夹，防止进入链接目标。
- 指纹是路径/大小/修改及创建时间等**元数据指纹**，不是内容哈希或 NTFS USN 历史。离线恢复完全相同元数据的特殊变化可能无法识别，也不保证抵御恶意并发路径替换。
- 回收站可恢复性取决于 Windows、磁盘和容量，网络盘等位置可能不支持。重要数据请保留备份，先用可丢弃文件试用。

## 托盘与自动任务

Windows 任务名为 `FolderNest Daily` 和 `FolderNest Logon`，不带版本数字。它们只是负责启动同一程序的每日/登录计划，不是每个目录各一个 Windows 任务。

有监控目录就自动维护这两条任务；停用只控制所选目录的扫描/提醒，不清空计时。即使全部停用，启动计划仍保留，方便以后打开程序管理；删除最后一个监控后自动移除启动计划。任务变更记录日志，失败会在主界面显示，手动扫描仍可用，不会虚报成功。

任务使用当前用户交互令牌，执行 `--background --data "实际数据目录"`，不保存密码、不申请管理员权限、不自动删除文件。程序旁若已有同名但不同数据位置/用户的任务，不会覆盖它们。同数据目录的旧 `FolderNest 2 <SID> Daily/Logon` 在新任务验证成功后备份 XML 并退役。

有监控目录时关闭主窗口会收起到托盘；“退出程序”停止本次进程，但保留 Windows 启动计划。再次正常启动唤回同数据目录的窗口。Windows 通知是否显示及展示多久受系统设置/勿扰模式控制，不保证常驻；始终可手动查看清单。

移动程序前先退出，移动 EXE 和**整个数据文件夹**，从新位置启动后会自动校正同数据位置的程序路径。若数据路径也改变，旧任务会被保护为不同数据位置，不会直接覆盖；应先在原位置删除全部监控（会清除对应计时），或在 Windows 任务计划程序中备份并删除旧的两条任务，再从新数据位置启动。若需要保留计时移动位置，建议备份数据后由熟悉任务计划的用户处理，勿只复制 EXE。

## 数据存储与备份

| 位置 | 内容 |
| --- | --- |
| `FolderNest.exe` | GUI、后台入口、运行时和独立图标 |
| EXE 旁 `data/foldernest.db` | SQLite：目录配置、顺序、首次发现/活动时间、设置、最近提醒日期 |
| `data/logs/foldernest.log`、`.log.1` | 当前/轮换日志，总额默认 10 MiB，可设 2–1024 MiB |
| `data/foldernest.lock` | 运行独占锁 |
| 已有 `data-v2/foldernest.db` | 同位置升级时优先复用，保留预览/2.0 记录 |
| `data/legacy-backup/` | 本机旧脚本 JSON、状态及旧任务 XML 的可恢复归档，不再自动加载 |
| `%LOCALAPPDATA%/FolderNest/v2` | 程序旁不可写时的备用数据目录，主界面明确显示 |
| 系统运行时缓存 | .NET 单文件原生库解压缓存，可能在用户临时目录，不属于配置 |

主界面底部显示**实际数据位置**。退出程序后备份整个数据文件夹，不要只复制正在使用中的 DB。日志包含本机路径，不会自动上传；个人数据库/配置/日志不进入 Git 或便携包。

## 升级与旧配置导入

- 现有 2.0 SQLite 数据直接读取，保留目录 ID、启用状态及计时；不需要重新导入。旧的“参与自动扫描”字段不再使用，所有启用目录统一自动扫描。
- 本次按用户要求仅归档旧脚本版 `config.json`、`state.json`、旧日志，不删除真实文件夹，不清空 2.0 记录。
- 如需导入脚本版配置：点击“导入旧版配置”，在 `data/legacy-backup/` 的归档子文件夹里选择 `config.json`。导入路径、天数、方式、启用状态，以新 ID 加入并从导入时重新计时；不导入旧 Pending/FirstSeen，不修改源 JSON。
- 重复/相互包含目录拒绝导入。已经在 2.0 列表里的目录无需再导入。
- `v1.0.0`、`v1.1.0`、`v2.0.0` 保留；2.1.0 不恢复旧脚本运行框架。

## 源码与构建

- `src/FolderNest.Core`：到期/提醒策略、扫描、选择性重置计时、清理复查。
- `src/FolderNest.Infrastructure`：SQLite、文件枚举/监听、回收站、Windows 任务及日志/导入。
- `src/FolderNest.Desktop`：WPF 主窗口、删除/重置/添加/设置/到期清单、托盘及单实例。
- `tests/`：规则、真实 Windows 隔离适配器、桌面组件回归。
- `scripts/build.ps1`：开发者构建/测试/发布，不是用户启动依赖。

Windows x64 + .NET 10 SDK。优先使用 `.tools/dotnet` 下 SDK，否则用 PATH 中的 dotnet：

```powershell
./scripts/build.ps1
./scripts/build.ps1 -Publish
```

仅构建发布包而不替换本机根目录 EXE，可用 `./scripts/build.ps1 -Publish -PackageOnly`；版本化暂存目录位于 `artifacts/release-v版本号/`，不会覆盖正在使用的旧 `artifacts/portable/`。

发布流程：Release 构建 → 行为测试 → 桌面组件测试 → 自包含 EXE → 独立数据启动测试 → 白名单 ZIP。测试只清理自动创建的测试文件、使用随机任务名，不处理个人监控文件。
