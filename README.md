# FolderNest 2.1.1

Windows 中文文件保留期限管理工具：加入监控开始计时，观察到文件变化刷新时间；到期后提醒，由你勾选确认后移入回收站或永久删除。

C# / .NET 10 + WPF + SQLite，自包含 Windows x64 便携 EXE。无需安装、无需另装 .NET，不依赖 PowerShell/CMD/VBS 启动，可以放在 D/E 盘等可写位置。

## 获取稳定版

从[稳定版 Releases](https://github.com/li-kyrie/FolderNest/releases/latest) 下载 `FolderNest-Portable-v2.1.1-win-x64.zip`，解压后双击 `FolderNest.exe`。不要将 GitHub 自动生成的 Source code ZIP 当作可运行软件。配套 `.sha256` 用于校验压缩包。

本机整套成品在 `D:\FolderNest\产品\FolderNest\`，源码在项目根目录 `src/`，本机压缩包在 `发布包/`。不再从根目录或 artifacts 启动旧程序。

## 快速开始

1. 双击成品目录的 `FolderNest.exe`。
2. “添加监控目录”选择真实目录，设置 1–36500 整数天数、删除模式及启用状态。
3. 保存后立即建立计时，下载文件携带的旧修改日期不会使其刚加入就到期。
4. 每日默认本地 **02:00** 检查，登录补扫。“设置”可修改每日时间、日志总额和新目录默认删除方式。
5. 只有存在到期项才通知。点击通知或“查看到期清单”，取消勾选不想处理的项目，确认后清理。

有监控时关闭窗口收起托盘；“退出程序”结束进程。GUI 有独立任务栏图标，不打开命令行窗口。无需联网。

## 常用操作

| 操作 | 作用 |
| --- | --- |
| 启用/停用选中 | 只作用于选中行；保留历史，日历不冻结。混合状态统一启用，全部启用则停用 |
| 删除监控任务 | 独立勾选窗口；删除配置及该目录计时，不删除实际文件；再添加重新计时 |
| 重置计时 | 独立窗口选择整目录或根文件/一级子文件夹；从确认时重新计时，不修改文件日期 |
| 扫描选中 / 扫描全部启用 | 扫描所选启用目录/全部启用目录；空选择不误扫全部 |
| 全选 / 全不选 | 列表右上角；支持 Ctrl 多选、Shift 范围选择 |
| 左侧排序柄 / 上移、下移 | 保存人工顺序，不改变计时；不支持拖动框选 |
| 双击路径 / 天数 / 下拉选项 | 合法编辑保存；无效路径红框提示，Esc 撤销；天数整数微调 ±1 |
| 导入监控配置 | 选择 JSON，校验并预览后新增，支持自编模板和旧脚本配置 |

## 数据与配置

主窗口底部同时显示实际**数据目录**及**配置文件（SQLite）**位置。

| 相对于成品 EXE 的位置 | 内容 |
| --- | --- |
| `data/foldernest.db` | SQLite：监控配置、设置、顺序、计时、最近提醒日期 |
| `data/logs/foldernest.log`、`.log.1` | 当前/轮换日志，总额默认 10 MiB，可设 2–1024 MiB |
| `data/legacy-backup/` | 本机升级和旧版资料归档，不自动加载 |
| `examples/monitor-config.example.json` | 可编辑的导入模板，不是自动同步配置 |
| `docs/` | 使用、配置、架构、验收等说明 |

EXE 旁不可写时使用 `%LOCALAPPDATA%/FolderNest/v2`，界面标明备用位置；已有 data-v2 数据优先复用。单文件原生运行库可能使用系统临时缓存。

备份前退出程序，复制整个实际数据目录。Git/发布包不含个人数据库、日志、备份或监控文件。导入 JSON 不覆盖已有监控、不恢复计时；导入后修改 JSON 不会自动更改程序。2.0/2.1 SQLite 升级直接复用，无需导入。

## 自启动、退出与计时须知

- **配置存储与导入不同**：`.db` 是 SQLite 数据库，保存实际配置和计时，通过 GUI 修改；“导入监控配置”只接受 `.json`，不接受 `.db`，导入后不持续同步源 JSON。
- **关窗口不等于退出**：有监控时点击 × 收起到托盘，继续工作；点击“退出程序”才结束进程，停止本次扫描、文件监听和提醒。
- **退出不取消自启动**：有监控时保留每日及登录两条 Windows 任务。当前用户登录后、每日设定时间（默认本地 02:00）可重新后台启动；不会主动弹出主窗口，扫描后继续驻留托盘。前提是任务有效、程序路径可用且用户已登录；关机时无法扫描，登录后补扫。
- **停用与删除不同**：全部目录停用也保留启动计划，但不扫描停用项；删除最后一个监控后自动移除两条计划。
- **计时不是后台秒表**：依据数据库里的时间计算到期日。退出或关机不会暂停/归零；再次启动时，未变化项目沿用原计时。
- **退出期间的修改会补查**：启用目录重启补扫时若检测到变化，从本次发现变化时重新计时，而非实际修改时。例如周一修改、周三补扫发现，保留 7 天就从周三重新计 7 天。新文件也从首次发现计时；一级子文件夹内部变化刷新该子文件夹整体计时。
- **变化判断有边界**：根据路径、大小、修改/创建时间等元数据判断，不逐字节比较内容；内容变了但这些信息完全恢复原样时可能漏检。有到期项才提醒，任何扫描或自动启动都不会自行删除文件。

## 原理与安全边界

- 根文件独立计时，一级子文件夹整体计时/清理，不是深层文件逐个计时。
- 添加时初始化已有项目；后来新项目从首次发现计时。修改按观察到变化时刻刷新，不用旧修改日期作为起点。
- 关机不能物理扫描，但已知截止时间继续推进，登录后补算；离线进入的文件只能从首次发现保守计时。
- 在线文件事件辅助跟踪，每 15 分钟全量校正，每日到点检查。每天最多提醒一次、不追催，清单实时计算，不保存冻结待删队列。
- 执行清理必须明确选择和确认，执行前再次校验配置、状态、路径和元数据指纹；变化/失联等情况跳过并记录。
- 筛选不会取消隐藏项勾选；确认框显示总数及永久删除数。
- 不解析 .lnk 目标，跳过符号链接/目录联接，拒绝清理内部含链接的子目录。不能监控程序/数据目录及其上下级。
- 元数据指纹不是内容哈希/NTFS USN 历史，不保证识别完全恢复元数据的离线变化或抵御恶意并发路径替换。
- Windows 通知受系统设置/勿扰控制，不保证常驻；回收站支持取决于磁盘、容量和网络位置。重要资料需备份，先用可丢弃文件试用。

Windows 全局计划名为 `FolderNest Daily`、`FolderNest Logon`，不是每个目录一个。程序自动维护，当前用户权限、不存密码。停用目录不卸载计划，删除最后一个监控后移除；失败显示在 GUI 和日志。

更新前退出，保留 data。移动软件需带整个数据目录；若数据绝对路径改变，旧计划受所有权保护，不会被静默覆盖。先备份数据和已核实的旧任务 XML，再从任务计划程序删除旧的两条计划，从新位置启动重建。不要同时使用两个数据副本。

## 源码与构建

保留核心源码、测试、图标、正式构建脚本及文档。成品集中在 `产品/FolderNest/`；大 EXE 不提交源码 Git，通过 Release 分发。

开发需要 Windows x64 + .NET 10 SDK。优先使用本机可选 `.tools/dotnet`，否则使用 PATH 中 SDK：

```powershell
./scripts/build.ps1
./scripts/build.ps1 -Publish
```

`-Publish` 构建/测试后更新 `产品/FolderNest/`（不覆盖 data），生成 `发布包/` 中的白名单 ZIP 和 SHA256。`-Publish -PackageOnly` 只暂存打包，不更新本机成品。`bin/`、`obj/`、`artifacts/` 是可再生中间产物，不是启动入口；整理时可删除。`scripts/build.ps1` 是正式开发工具，应保留。
