# FolderNest 统一需求规格

整理日期：2026-10-10。以用户后续修正覆盖前面的建议。项目名及仓库沿用 FolderNest，全部开发、构建和 Git 操作在 `D:\FolderNest` 完成。

## 1. 产品目标与交付

| 编号 | 最终要求 | 验收方式 |
|---|---|---|
| P01 | Windows 中文本地桌面小程序，所有日常设置均可在 GUI 完成 | 无需手工编辑配置或执行命令 |
| P02 | 优先便携、下载解压即用；程序位置可自定义，不要求 C 盘或安装包 | 自包含 `FolderNest.exe` 可从 D/E 盘启动 |
| P03 | 独立图标、独立任务栏窗口；运行时只显示 GUI | 不保留 PowerShell/cmd 窗口 |
| P04 | 保存 Git 历史，更新个人仓库和 README，版本使用语义化标签 | 原版 `v1.0.0`，多目录原型 `v1.1.0`；不改写历史标签 |
| P05 | 构建产物放 D 盘；旧 Codex 工作目录不再使用 | 当前工作根目录始终 `D:\FolderNest` |
| P06 | 借鉴同类工具的技术与交互，但以本项目的计时及确认流程为准 | 保留调研参考和框架取舍说明 |

## 2. 多目录及配置

| 编号 | 最终要求 | 规则 |
|---|---|---|
| M01 | 多个监控目录 | 每个目录有稳定 ID，独立路径、天数、删除模式、启用状态、自动扫描选择 |
| M02 | 添加、编辑、启用/停用、删除某个监控目录 | 全部 GUI 操作 |
| M03 | 删除监控只删除配置及该目录的计时元数据 | 不删除真实目录；其他目录计时不受影响 |
| M04 | 停用暂停手动及自动扫描 | 历史记录保留；再次启用先扫描；日历时间继续推进，不自动重新开始计时 |
| M05 | 固定选项使用下拉，禁止任意文本 | 状态：启用/停用；删除模式：回收站/永久删除 |
| M06 | 路径允许在列表直接修改 | 验证为存在、可访问的绝对文件夹路径；无效时提示、拒绝保存；修改为新目录时重置该监控历史 |
| M07 | 天数允许直接修改 | 整数 1–36500；拒绝小数、空值、负数、文本；提供可点击的上下按钮，每次 ±1，支持键盘上下键 |
| M08 | 配置修改与持久数据同步 | 通过验证后提交；失败保留旧配置并展示原因，不显示虚假成功 |
| M09 | 防止重复/包含目录导致重复清理 | 拒绝相同和相互包含的监控路径；禁止整个磁盘、程序目录及数据目录的上级目录 |

M04 的“保留历史、不冻结日历”、M09 的重复路径处理是本次明确的实现约定；用户此前并未提出停用时暂停日历。

## 3. 进入时间及到期规则

| 编号 | 最终要求 | 规则 |
|---|---|---|
| T01 | 从文件进入监控目录开始计时，类似回收站保留期限 | 在线时用文件系统事件辅助记录，事件丢失后用全量扫描校正 |
| T02 | 下载带 2024 年旧修改时间的文件不得立即误判过期 | 首次发现作为下限；原修改/创建时间不替代进入时间 |
| T03 | 首次启用时已有文件 | 无可验证进入时间，统一从首次发现开始计时，并明确告知 |
| T04 | 关机不停止已记录项目的保留天数推进 | 记录 UTC 锚点和截止时间，开机直接计算是否到期，无需后台持续累加计数 |
| T05 | 关机期间仍希望每日 2 点检查积累 | 物理扫描不可能在关机中执行；开机补扫，按已记录截止时间得到截至当时应到期的全部项目 |
| T06 | 未运行期间进入的文件 | 普通目录无法可靠还原进入时刻，首次发现保守计时；不得承诺精确还原关机期间历史 |
| T07 | 目录内更新可刷新计时 | 默认根目录单文件独立；一级子文件夹为整体清理单元，内部新增、删除、可观察修改刷新整个单元有效时间 |
| T08 | 链接目标修改不影响当前监控目录 | `.lnk` 按普通文件处理；不解析快捷方式目标；跳过符号链接/联接/其他重解析点，不递归到外部目录 |
| T09 | 空目录与暂时不可访问目录 | 空目录正常完成；访问失败保留上次元数据并日志记录，不能当作所有文件已消失 |
| T10 | 批量/局部扫描 | 仅更新本次扫描的目录；其他目录记录不丢失；停用、未自动选择的目录记录保留 |

T07 沿用对话中已有原型的清理单元约定，并非用户新要求。未来可增加“全部文件独立”模式，但不在本次框架范围内。观察到文件修改时按观察时刻刷新，而不是采用下载文件携带的旧时间。元数据指纹无法识别“内容变化后又恢复相同长度和时间”的特殊情况，后续事件追踪用于补足。

## 4. 每日扫描、在线提醒与任务部署

| 编号 | 最终要求 | 规则 |
|---|---|---|
| S01 | 每天轮询一次，并可 GUI 设置时间 | 默认沿用现有 02:00；UI 显示 24 小时制，允许改为 14:00 等 |
| S02 | 扫描与提醒分离 | 扫描只更新状态；提醒在用户已登录、可交互会话中发生 |
| S03 | 2 点后才开机则开机补提醒 | 首次在线补扫后，有到期项目才提醒；当天时间之前登录，仅建立跟踪并等指定时间 |
| S04 | 连续几天不关机 | 每天在指定时间判断并提醒，有清单的日子才提醒 |
| S05 | 没看到/没处理提醒 | 不追催、不要求维持永久待处理窗口；后续日常触发按当时状态重新判断 |
| S06 | 无到期项则保持安静 | 不弹通知、不弹自动清单；手动查看可在状态栏提示为空 |
| S07 | Windows 通知消失不控制清理 | 可用 Toast + 托盘入口；通知展示时长由系统决定；点击才打开可勾选窗口 |
| S08 | 安装定时任务前选择参与目录 | 只勾选需要自动扫描的启用目录；未选目录仍可手动扫描 |
| S09 | 没有目录/没有选择时不得显示成功 | 明确提示并日志记录；部署失败、部分成功同样明确显示 |
| S10 | GUI 显示实际已部署/未部署/部分部署/无法查询 | 总体任务状态、每目录是否参与；不能仅凭配置勾选显示“已部署” |
| S11 | 删除目录配置、取消目录自动选择、卸载全局任务相互独立 | 删除/取消某目录后不再自动扫描它；卸载任务保留目录配置并停止全部自动扫描 |
| S12 | 任务日志 | 记录每日/登录任务名称、路径、选中的目录、时间、部署/卸载结果和失败原因 |

采用少量全局任务＋目录选择，而不是每目录建一组 Windows 任务。删除最后一个目录时全局任务可保留，但空配置不发提醒；界面明确展示全局状态并可卸载。时间按配置时区触发，元数据始终 UTC。睡眠、错过计划、跨日登录需要补偿调度；关机不能靠唤醒设置解决。

## 5. 清单、删除与日志

| 编号 | 最终要求 | 规则 |
|---|---|---|
| C01 | 先列出到期清单，可以取消勾选具体项目，再确认处理 | 默认勾选、全选、全不选、筛选、确认、取消 |
| C02 | 回收站/永久删除可设定 | 每目录默认回收站；清单展示本次模式；永久删除显式确认 |
| C03 | 清理只来自用户的清单确认 | 扫描/定时/提醒组件不调用清理执行；不引入“超时自动删除” |
| C04 | 不要求持久保存待处理清单 | 持久保存进入时间/活动时间等元数据；到期清单是实时派生结果，不冻结旧清单；取消勾选不永久豁免该项目 |
| C05 | 删除前再校验目标 | 目标仍属于配置、未更新、不是链接替换、仍存在且仍到期；逐项记录结果；失败不丢计时记录 |
| L01 | 所有关键动作日志记录 | 添加/修改/启停/移除监控、扫描、提醒、部署、卸载、删除及错误 |
| L02 | 日志有大小上限 | 默认总计 10 MiB（当前 5 MiB + 一个 5 MiB 轮换文件）；后续 GUI 可设置额度 |
| L03 | 本地数据位置可知 | 程序旁 `data` 为正式目标；框架阶段使用 `data-v2` 避免混入旧数据；不可写则明确显示 LocalAppData 备用位置 |

用户拒绝将“未操作不删除”“永久待处理清单”单独扩展成工作流；但最初始终要求“同意后执行”。C03 保留这个确认触发条件，C04 不将清单本身做成永久队列。

## 6. 图形界面交互

| 编号 | 最终要求 | 规则 |
|---|---|---|
| U01 | 顶部功能区高度随按钮行数变化 | WrapPanel 自动换行；窗口缩放不裁掉下一行，不留固定大空白 |
| U02 | 添加目录对话框保留原尺寸 | 正式编辑窗设计尺寸 560×240；“启用此监控目录”完整单行；框架暂用系统文件夹选择器 |
| U03 | 保存后立即出现在列表 | 配置保存成功后添加，稳定对象绑定，无事件作用域丢结果 |
| U04 | 操作后保持选中行和光标 | 按钮操作不重建列表；恢复原 CurrentItem、选中集和滚动位置；已删除行只能选择邻近行 |
| U05 | Ctrl+左键多选、Shift 范围选择 | 原生 Extended 选择模式 |
| U06 | 鼠标拖动框选 | 从列表空白处开始，绘制框选区域，避免与单元格编辑、下拉、微调按钮冲突 |
| U07 | 对多行批量扫描、启停、删除监控 | “扫描选中”仅处理选中且启用目录；混合启用状态时统一启用，全部启用时统一停用 |
| U08 | UI 操作无需手改 JSON/任务命令 | 路径、时间、模式、任务选择、日志限额均最终 GUI 可配置 |

## 7. 历史原型问题与验收底线

旧脚本并不能证明上述需求已经正确实现。代码核对发现：鼠标事件中局部变量无法可靠跨事件保存；网格方向键改值不一定写配置；编辑控件复用可能把天数方向键行为带到路径栏；停用后全量扫描丢记录；修改后 Pending 未回退；重建行影响选择；“已选”不等于部署；`.cmd` 即使转发 VBS 仍可能短暂闪窗；通知与扫描混在一起。这些由正式框架的类型化状态、验证、独立服务和行为测试解决。

不把上次回复中“已验证 GUI”的表述视为证据：此前实际执行的主要是语法和命令行扫描，并没有完成真实图形交互验证。
